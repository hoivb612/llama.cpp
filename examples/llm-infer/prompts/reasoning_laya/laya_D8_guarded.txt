# --- Guard battery -----------------------------------------------------------
# Laya scores every option positively, so the catch-all option 'z' can never win
# a choice: there is no text for "none of the above" to be similar to. In the
# unguarded run it fired 0 times out of 10, losing to 'b'/'c' at up to p=0.985.
#
# These questions detect positively what 'z' describes negatively. Everything
# else falls through to '@choice', which already matched the literal number
# well (8/10 on the 585584 block).
#
# Three wordings were tried and rejected before this battery, each failing one
# of the two design rules documented in custom_prompts_laya.txt:
#   "suggests phoning somebody other than Josie"        -> ~50% recall, 0 FP
#   "mentions the names Nicky, Tanya, Barry, Sophie..." -> fired 29/40: the
#        names are in the STATE (the phonebook), so it matched the state, not
#        the reply. Rule 1 failure at state level.
#   "calls it his number or her number, not Josie's"    -> fired HIGHEST on the
#        correct block: "not Josie's number" was ignored and "Josie's number"
#        matched. Rule 2 failure (never use negation).
#
# What worked was not a better single wording but an OR of four weak ones. No
# single probe separates the deflections, but each catches a different subset
# with no false positives, so the union is strictly better than any one.
#
# Diagnostic tip: run --mode noul with every candidate wording present at once
# and read the score columns. One run A/Bs the whole battery.

LAYA_POLICY
# No single wording separates the deflections cleanly: each one catches a
# different subset. The policy is an OR battery -- every rule is thresholded
# just under its own false-positive floor (the highest score it reaches on a
# non-deflecting utterance), so adding rules only ever adds recall.
#   d_else  non-z max 0.408   d_try non-z max 0.692
#   d_might non-z max 0.661   d_who non-z max 0.708
d_else    > 0.42 -> z
d_try     > 0.70 -> z
d_might   > 0.67 -> z
d_who     > 0.72 -> z
dont_know > 0.70 -> e
*                -> @choice
END_SECTION
